# Mise Design System

This is the design source of truth for the client and is synchronized with
`apps/client/src/index.css`.

> Change tokens in this file first, then update
> `apps/client/src/index.css` in the same change.

The visual direction is calm, editorial, kitchen-oriented, bilingual, and
evidence-aware. Themes may change atmosphere, but semantic meaning and
component behavior must remain stable.

No token changed with the iOS scaffolding. Platform boundaries are:

- The generated Capacitor WebView renders the same React client, so it uses
  this document’s semantic tokens, typography, breakpoints, media rules,
  motion behavior, and safe-area-aware layout without a native theme fork.
  Source remains `apps/client/src/index.css`; the copy under
  `apps/client/ios/App/App/public/` is generated by `ios:sync`.
- The source-only Share Extension is not a WebView and is not an Xcode target.
  Until it is integrated, its UIKit UI uses iOS system typography, dynamic
  system colors, standard controls/alerts, and platform accessibility
  conventions. It must not create a second branded primitive or token system.
- Neither native surface has been compiled or visually/accessibility tested in
  Xcode. “Capacitor shell generated” does not mean native/share integration is
  complete.

## Static brand asset fallback palette

These four fixed colors are the exact fallback palette for generated/native
raster or SVG brand assets where CSS semantic variables cannot be resolved:

| Name | Hex | Current generated use |
|---|---|---|
| Terracotta | `#B75235` | App-icon background and splash mark tile |
| Cream | `#FFF8E9` | Brand-mark strokes and splash background |
| Peach | `#F2C9A9` | Lower brand-mark accent stroke |
| Dark text | `#3A2C25` | Static “Mise” splash lettering |

They are asset-production constants, not business-UI tokens and not a fourth
theme. Web and Capacitor WebView business UI must continue to use semantic CSS
variables. The native Share Extension must continue to use iOS dynamic system
colors while it remains a source-only scaffold; it must not adopt this fixed
palette as a parallel branded primitive system.

`apps/client/scripts/generate-ios-assets.mjs` renders the inline brand SVG to a
1024×1024 app-icon PNG and a 2732×2732 splash PNG, then copies the splash to the
three filenames referenced by the Xcode 1x/2x/3x catalog entries. Regenerate
them with:

```sh
pnpm --filter @mise/client ios:assets
```

The command uses Playwright and Chrome (`CHROME_PATH` or the script’s default
executable). A fallback-palette change must update this file first and then the
generator. It does not require changing `index.css` unless the semantic UI
tokens are also intentionally changing.

Use semantic names in components. Do not select a theme-specific color
directly. Tailwind maps these properties to utilities such as `bg-background`,
`text-muted-foreground`, `border-border`, and `ring-ring`.

### Semantic roles

| Token group | Use |
|---|---|
| `background` / `foreground` | App canvas and default text |
| `card`, `popover` | Raised content and overlays with paired foregrounds |
| `primary` | Main action, current focus, active progress, branded emphasis |
| `secondary` | Quiet icon wells and supporting actions |
| `muted` | Subtle grouping surfaces; `muted-foreground` for secondary copy |
| `accent` | Limited complementary emphasis, not a replacement for status |
| `destructive` | Errors, blocking conflicts, destructive actions |
| `success` | Ready, complete, confirmed |
| `warning` | Needs review, uncertainty, non-blocking attention |
| `info` | Informational and processing states |
| `border`, `input`, `ring` | Structure, form boundaries, keyboard focus |
| `surface-raised` | Elevated review/editor surfaces |
| `surface-sunken` | Inset groups, tracks, and media placeholders |
| `surface-media` | Dark media chrome and overlays |
| `sidebar-*` | Navigation-specific equivalents |

Alpha modifiers such as `/8`, `/10`, `/15`, `/25`, and `/95` are used for
subtle surfaces and overlays. Do not encode status using alpha or color alone;
pair it with a label and, when useful, an icon.

These CSS variables also govern the web client inside Capacitor. Do not
hard-code an iOS-only WebView palette. The Share Extension does not consume CSS
variables: its scaffold uses `systemBackground` and UIKit’s inherited dynamic
label/control colors so light/dark mode and increased-contrast behavior remain
platform-owned until a deliberately documented integration exists.

## Typography

### System font stacks

```css
--font-sans:
  -apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC",
  "Hiragino Sans GB", "Noto Sans CJK SC", "Segoe UI", sans-serif;

--font-display:
  ui-serif, "Iowan Old Style", "Songti SC", "Noto Serif CJK SC", Georgia,
  serif;
```

Use sans for UI, fields, controls, metadata, and long functional copy. Use
display serif for product/recipe titles, section headings, and timer numerals.
No external font download is part of the system.

Inside the Capacitor WebView, these same stacks resolve to installed iOS system
fonts where available. The Share Extension remains native system UI: its
status label uses `UIFont.preferredFont(forTextStyle: .body)`, and alerts and
controls retain UIKit defaults. Do not reproduce the web display-serif scale
or hard-code point sizes in the extension merely to make it look branded.

### Full implemented type scale

The scale is Tailwind 4's default scale, plus the implemented 11 px micro size.

| Name / utility | Size | Default line height | Current use |
|---|---:|---:|---|
| Micro / `text-[11px]` | 11 px | contextual normal line box | Mobile navigation and compact brand tagline only |
| XS / `text-xs` | 12 px | 16 px | Eyebrows, badges, timestamps, helper copy |
| SM / `text-sm` | 14 px | 20 px | Controls, body support copy, metadata |
| Base / `text-base` | 16 px | 24 px | Primary body and mobile form text |
| LG / `text-lg` | 18 px | 28 px | Section titles and emphasized body |
| XL / `text-xl` | 20 px | 28 px | Card and compact page titles |
| 2XL / `text-2xl` | 24 px | 32 px | Section and sheet titles |
| 3XL / `text-3xl` | 30 px | 36 px | Mobile page titles |
| 4XL / `text-4xl` | 36 px | 40 px | Desktop page titles and timers |
| 5XL / `text-5xl` | 48 px | 48 px | Large recipe/welcome display titles |

Display hero titles override line height to `1.08` and tracking to `-0.025em`.
Eyebrows use bold uppercase sans at 12 px with `0.12em` or `0.14em` tracking.
`leading-relaxed` is used for descriptive copy; `leading-snug` for compact
headings. Bilingual secondary content may use `0.88em` relative to its primary
line and always uses normal weight plus muted color.

Approved weights are 400 normal, 500 medium, 600 semibold, and 700 bold.
Use `tabular-nums` for timers, quantities, progress, and timestamps.

## Spacing

Tailwind's numeric spacing utilities use a 4 px base:

```text
spacing(n) = n × 4 px
```

| Token | px | Typical use |
|---:|---:|---|
| 0 | 0 | Reset |
| 1 | 4 | Tight inline gap |
| 2 | 8 | Control/icon gap |
| 3 | 12 | Compact padding and group gap |
| 4 | 16 | Default card/page-mobile spacing |
| 5 | 20 | Comfortable card padding |
| 6 | 24 | Section/card spacing and small-screen gutters |
| 7 | 28 | Large card padding |
| 8 | 32 | Desktop gutters and section separation |
| 10 | 40 | Large panel padding |
| 12 | 48 | Hero/empty-state vertical spacing |
| 14 | 56 | Large desktop hero padding |
| 16 | 64 | Major shell/nav dimension |
| 20 | 80 | Reserved large separation |
| 24 | 96 | Large vertical region / minimum field area |
| 28 | 112 | Mobile content clearance |
| 36 | 144 | Large media/card minimum |

Implemented optical exceptions are half-steps `0.5` (2 px), `1.5` (6 px), and
`2.5` (10 px), used only for compact alignment such as badge padding,
micro-gaps, and fine offsets. One-pixel borders and `gap-px` are structural,
not spacing rhythm. Prefer the integer 4 px scale for new layout.

## Radius and shadow

### Radius tokens

```css
--radius: 1rem;                         /* 16 px */
--radius-sm: calc(var(--radius) - 6px); /* 10 px */
--radius-md: calc(var(--radius) - 4px); /* 12 px */
--radius-lg: var(--radius);             /* 16 px */
--radius-xl: calc(var(--radius) + 6px); /* 22 px */
```

- Small controls/checkboxes: `sm`.
- Inputs, standard buttons, and nested surfaces: `md`.
- Cards, tabs, icon wells, and normal panels: `lg`.
- Major page shells and hero panels: `xl`.
- Badges, status chips, step numbers, and avatars: full pill/circle.

### Shadow tokens

```css
--shadow-xs:
  0 1px 1px color-mix(in oklab, var(--foreground) 5%, transparent);
--shadow-sm:
  0 1px 2px color-mix(in oklab, var(--foreground) 6%, transparent),
  0 4px 12px color-mix(in oklab, var(--foreground) 5%, transparent);
--shadow-md:
  0 2px 4px color-mix(in oklab, var(--foreground) 7%, transparent),
  0 12px 30px color-mix(in oklab, var(--foreground) 8%, transparent);
--shadow-sheet:
  0 -8px 32px color-mix(in oklab, var(--foreground) 12%, transparent);
```

Use `xs` for normal separation, `sm` for hover/elevated shells, `md` only for
strong elevation, and `sheet` for fixed sheets or bottom controls. Borders
remain the primary structure; do not stack multiple strong shadows.

## Layout and breakpoints

### Breakpoints

| Name | Minimum width | Current behavior |
|---|---:|---|
| Base | 320 px | Supported minimum; mobile shell and bottom navigation |
| `sm` | 640 px | Wider gutters, paired controls, responsive typography |
| `md` | 768 px | Two-column collections |
| `lg` | 1024 px | 252 px desktop sidebar; review source/editor split; cook split |
| Custom review | 1440 px | Review adds persistent issue column |
| `xl` | 1280 px | Three-column recipe grid and four theme previews |
| `2xl` | 1536 px | Tailwind standard available; no distinct current rule |

At 1024–1439 px, review uses `42fr / 58fr` and opens issues in a Sheet. At
1440 px and wider, it uses `34fr / 42fr / minmax(19rem, 24fr)`.

### Constraints

- Document minimum width: 320 px; minimum app height: `100svh`.
- Mobile page gutter: 16 px; `sm`: 24 px; `lg`: 32 px.
- Desktop sidebar: fixed 252 px.
- Welcome shell: max 1440 px.
- Library, recipe detail, collections: max 1280 px.
- Import: max 1180 px.
- Settings: max 1024 px.
- Cook content: max 1152 px; cook header/footer: max 1280/1152 px.
- Review: max 1680 px.
- Sticky headers, fixed bottom navigation, and cook controls use
  `safe-area-inset-top/bottom` helpers.
- Main mobile shell reserves 112 px below content; desktop reserves 40 px.

The Capacitor WebView keeps these constraints and safe-area helpers; do not add
a second native inset system around the web shell without evidence from an
Xcode/device test. The Share Extension’s compact native view follows UIKit
layout margins and Auto Layout rather than web breakpoints.

Use grids for page-level relationships and flex for small groups. Keep reading
copy constrained (`max-w-lg`, `max-w-2xl`, or `max-w-3xl`) even when the
surrounding page is wider.

## Media

| Context | Ratio / behavior |
|---|---|
| Recipe card and static cover illustration | 4:3 |
| Step media and review source | 16:9 |
| Welcome storyboard banner | 2:1 (`16/8`) |
| Collection thumbnail | 4:3 on mobile; fills fixed desktop column |
| Recipe hero | Fluid panel with 18 rem mobile, 24 rem small, 31 rem desktop minimum height |

Use `object-cover`, a `surface-media` or `surface-sunken` fallback, meaningful
alt text for informative recipe/step imagery, and empty alt text for decorative
collection art. Do not imply a fixture illustration is a captured live frame.

Static covers are 800×600 SVGs; static step media is 800×450. Production media
should preserve these presentation ratios even when source dimensions differ.

## Primitive component patterns

Implemented in `apps/client/src/components/ui/primitives.tsx`:

- **Button:** default, secondary, outline, ghost, destructive, soft, and link
  variants; small (32 px), medium (40 px), large (48 px), and 44 px icon sizes.
  All include focus rings, disabled opacity, and a reduced-motion-safe active
  press.
- **Badge:** neutral, primary, success, warning, info, destructive, and
  outline; 24 px minimum height, pill radius, label-first semantics.
- **Card:** semantic card surface, 16 px radius, one-pixel border, `xs` shadow.
- **Input/Textarea/Select/Label:** semantic input border and background,
  visible focus border/ring, 44 px input/select minimum, and 16 px input text
  to avoid mobile zoom.
- **Checkbox:** 24 px square Radix control with check indicator and focus ring.
- **Progress:** 8 px semantic track; primary indicator animates with the slow
  duration.
- **Tabs:** 44 px list container, 36 px triggers, card/foreground active state.
- **Sheet:** Radix Dialog mounted from the right, full width up to `max-w-md`,
  media overlay, sheet shadow, accessible title/description, and labeled close.

Extend these primitives through variants before writing a parallel one-off
control. Keep interactive targets at least 40 px, preferably 44 px.

## Domain component patterns

Implemented in `apps/client/src/components/domain/` and `layout/`:

- **AppLogo / AppShell:** custom Mise mark, responsive sidebar/bottom nav,
  fixture marker, skip link, and offline state.
- **SourceBadge:** platform plus content type; visual style is secondary to the
  text label.
- **EvidenceBadge:** explicit, corroborated, inferred, missing, conflict, and
  user-confirmed states, each with icon, label, and semantic color.
- **LocalizedContent / BilingualToggle:** translated/original/bilingual
  display with source-text fallback.
- **IngredientRow:** quantity, preparation, optional/evidence state, and a
  cook-mode checkbox variant.
- **StepCard:** detail, review, cook, and compact variants; source range,
  evidence, temperature, duration, media, and step ingredients.
- **RecipeCard:** 4:3 visual or compact row, source/status, favorite action,
  time, tag, and update date.
- **SyncStatus:** saved, saving, offline, conflict, and error labels.
- **EmptyState:** dashed quiet panel, icon well, clear title/copy/actions.
- **ProcessingTimeline / ImportJobCard:** seven-stage fixture progress and
  explicit active, review, complete, failed, cancelled, or frozen states.
- **ReviewIssueCard:** severity, candidate, evidence jump, resolve/ignore, and
  closed state.
- **ThemeSwitcher:** four previews (three themes plus system) with pressed
  state.
- **CookStep:** step media/instruction, timer controls, completion, and
  per-step ingredients.

Evidence and processing patterns must always distinguish source facts,
inference, conflicts, user confirmation, and fixture simulation.

## Icons

- Import named icons from `lucide-react`; do not add a second icon library.
- Standard inline icon: 16 px (`size-4`).
- Primary button/navigation icon: 20 px (`size-5`).
- Feature/empty-state icon: 24 px (`size-6`); the no-media illustration uses
  28 px (`size-7`).
- Compact badge icon: 12–14 px (`size-3` or `size-3.5`).
- Keep Lucide's default stroke. The Checkbox check uses `strokeWidth={2.5}`;
  play controls may use `fill="currentColor"` intentionally.
- Decorative icons receive `aria-hidden="true"`.
- Icon-only buttons require an `aria-label` or visually hidden text.
- Do not rely on an icon or color alone for status. Keep the adjacent label.
- The custom Mise mark and favicon are brand assets, not Lucide replacements.

## Motion

```css
--duration-fast: 120ms;
--duration-base: 180ms;
--duration-slow: 260ms;
--ease-standard: cubic-bezier(0.2, 0, 0, 1);
```

- Fast: button, border, color, and card-hover feedback.
- Base: image scale and cook progress width.
- Slow: progress indicators and larger state movement.
- Keep motion functional and subtle. Current card media scales only to
  `1.015`; button press moves by one pixel.
- Sheets use open/close animation classes, with no decorative choreography.

For `prefers-reduced-motion: reduce`, global CSS sets scroll behavior to auto,
animation and transition duration to `0.01ms`, and animation iteration count to
one. Components also remove spinner, transform, and transition behavior where
needed. New motion must honor this behavior.

## Accessibility

- Maintain keyboard operation and a visible two-pixel semantic focus ring.
- Preserve the skip link and logical heading order.
- Use semantic buttons/links instead of clickable generic containers.
- Minimum supported viewport is 320 px; prevent horizontal overflow.
- Prefer 44 px touch targets; never go below the implemented 40 px standard
  for normal controls.
- Label every field. Use `aria-describedby` for validation feedback and
  `aria-invalid` for invalid values.
- Keep `aria-live` restrained: polite for saves/progress, assertive only when a
  timer reaches zero.
- Use `aria-pressed`, `role="status"`, `role="timer"`, tab semantics, and
  dialog title/description where implemented.
- Informative media gets localized alt text; decorative art and icons are
  hidden from assistive technology.
- Status cannot depend on hue alone. Include text and usually an icon.
- Preserve safe-area padding, reduced motion, and sufficient contrast in all
  three themes.
- Do not place essential controls only on hover.
- Validate the Capacitor WebView with VoiceOver, Dynamic Type effects on the
  web layout, increased contrast, reduced motion, light/dark appearance, and
  device safe areas once an Xcode build is available.
- Keep Share Extension status/error content available as text, use UIKit
  preferred fonts and dynamic colors, preserve standard alert semantics, and
  test VoiceOver/Dynamic Type before calling the target usable. Its current
  source has not been compiled or accessibility-tested.

## Internationalization and content

- Supported UI locales are `en-US` and `zh-CN`; both translation resources
  must keep identical key sets.
- Put interface copy in `apps/client/src/i18n/resources.ts`, not directly in
  JSX.
- Native Share Extension strings live separately in
  `apps/share-extension/Resources/en.lproj` and `zh-Hans.lproj`; keep matching
  `Localizable.strings` and `InfoPlist.strings` keys. Those files remain an
  unwired scaffold until localized variant groups are added to an Xcode target.
- Interface locale is independent from recipe-content display.
- Every source-derived text value preserves `original` and `originalLocale`.
  Chinese and English translations are additive.
- Content display modes are translated, original, and bilingual. Bilingual
  mode places the current locale first and source text second.
- If a translation is absent, show source text and expose the fallback to
  assistive technology; do not show a blank string.
- Preserve source units and wording when conversion is unreliable. Never
  invent a precise amount for “to taste,” “a handful,” or another unknown.
- Use locale-aware dates/search and tabular numerals for times/quantities.
- Keep platform names as proper nouns. Keep technical fixture labeling clear
  in both languages.
- Write short, direct actions and calm explanatory/error copy. Avoid hype,
  blame, and claims that an unconfigured service worked.
- Layout must tolerate longer English labels and dense Chinese text without
  fixed text heights.

## Do / don't

### Do

- Update this file first and `index.css` second for token changes.
- Use semantic colors and the existing primitives/domain patterns.
- Keep the 4 px layout rhythm and reserve half-steps for optical alignment.
- Preserve source provenance, uncertainty, and bilingual hierarchy.
- Pair status color with text and iconography.
- Test every component in all themes, both locales, keyboard navigation,
  narrow mobile, wide desktop, and reduced-motion mode.
- Label fixture media and processing as fixture behavior.
- Use this same system for the web client in Capacitor; use iOS system
  typography, dynamic colors, standard controls, and accessibility behavior
  for the native extension until an integrated cross-surface design is
  deliberately specified.
- Limit `#B75235`, `#FFF8E9`, `#F2C9A9`, and `#3A2C25` to static generated
  brand assets that cannot resolve semantic CSS variables.

### Don't

- Do not hard-code theme colors in components or create theme-specific JSX.
- Do not use a raw palette color to represent success, warning, info, or error.
- Do not add external fonts or another icon library without revising this
  system deliberately.
- Do not fork WebView tokens/layout for iOS or create a parallel branded UIKit
  primitive/token layer for the Share Extension.
- Do not use the static brand-asset fallback hex values directly in business
  UI components or treat them as semantic status/surface colors.
- Do not create one-off buttons, badges, cards, fields, or status chips when a
  current variant can express the need.
- Do not shrink body/form text below 16 px where mobile input zoom is a risk.
- Do not use color, animation, hover, or an icon as the only carrier of
  meaning.
- Do not crop step evidence into a misleading moment or describe fixture art
  as live captured media.
- Do not translate away original source wording or silently “correct” unknown
  quantities.
